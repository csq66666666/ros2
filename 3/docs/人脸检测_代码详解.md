# 第一部分 · 先看全局

## 1.1 一句话说清三个文件

> **`learn_face_detect.py` 是"一个人干活"，`face_detect_node.py` + `face_detect_client_node.py` 是"两个人配合干活"。**

| 文件 | 一句话 | 有没有 ROS |
| --- | --- | --- |
| `learn_face_detect.py` | 打开一张图片，找出人脸，画框，弹窗给我看 | ❌ 完全没有 |
| `face_detect_node.py` | **服务端**：别人把图片发给我，我找出人脸，把坐标报回去 | ✅ 提供服务 |
| `face_detect_client_node.py` | **客户端**：我把图片发过去，等服务端报坐标回来，我画框 | ✅ 请求服务 |

关键在于：**"找人脸"这个本领，三个文件用的是同一句代码。**

```python
face_recognition.face_locations(图片, number_of_times_to_upsample=1, model="hog")
```

- 在 `learn_face_detect.py:37`，它的输入是本地文件，输出直接给 `cv2.imshow` 显示。
- 在 `face_detect_node.py:41`，它的输入是请求里收到的图，输出填进 `response` 发回去。

**学会了单机版，你其实已经学会了服务端的核心。**

---

## 1.2 为什么非要拆成三个文件

初学者最常问：既然逻辑一样，写一个文件不行吗？

因为这三个文件解决的是**三个不同的问题**：

| 问题 | 谁来解 | 为什么不能合并 |
| --- | --- | --- |
| 我怎么知道 `face_recognition` 怎么用？ | `learn_face_detect.py` | 先把算法调通，不用管网络通信 |
| 别的程序怎么调用我的人脸检测？ | `face_detect_node.py` | 它得**一直开着**等人来问 |
| 我怎么去问别人？ | `face_detect_client_node.py` | 它**问完就退出**，和上面那个生命周期完全不同 |

★ 最重要的区别：**服务端要一直活着（常驻），客户端问一次就结束**。这两件事没法写在同一个函数里。

## 1.3 全局关系图

```
              chapt4_interfaces/srv/FaceDetector.srv
        （契约文件：规定"请求里有什么、响应里有什么"）
                              │ 编译时生成 FaceDetector 类
   setup.py ──────────────────┤
   (entry_points/data_files)  │
                              ▼
              colcon build ──▶ install/ 目录
                              │
        ┌─────────────────────┼─────────────────────┐
        ▼                                           ▼
 learn_face_detect.py                    face_detect_node.py（服务端）
 单机 · 完全不用 ROS                      常驻进程 · 等 /face_detect 请求
   读 default.jpg                            收图 → cv_bridge 转成 OpenCV
        ↓                                          ↓
   face_locations()  ◄──── 同一句核心代码 ────►  face_locations()
        ↓                                          ↓
   cv2.rectangle 画绿框                       填 response：number / use_time
        ↓                                        / top[] right[] bottom[] left[]
   cv2.imshow 弹窗                                 ↓ return response
                                                   ▲ request：整张图
                                                   │ response：坐标数字
                                                   ▼
                                    face_detect_client_node.py（客户端）
                                    一次性 · 跑完就退出
                                      读 png → cv_bridge 转 ROS 消息 → call_async
                                        ↓ 等 response 回来
                                      按坐标画蓝框 → cv2.imshow 弹窗
```

**三条最重要的关系：**

1. **共用核心**：单机版和服务端用的是同一句 `face_recognition.face_locations()`。
2. **检测只在服务端**：`face_detect_client_node.py` 里**没有** `import face_recognition`，它只负责打包、发送、收数字、画框。
3. **靠契约连接**：服务端和客户端都 `import` 同一个 `chapt4_interfaces.srv.FaceDetector`，两边必须用同一个"菜单"。

## 1.4 一张图片的完整旅程

以"服务版"为例，从你敲命令到看见弹窗，按时间顺序：

| 步骤 | 谁在做 | 发生了什么 |
| --- | --- | --- |
| ① | 你 | 终端 1 敲 `ros2 run demo_python_service face_detect_node` |
| ② | 服务端 | `main()` → `rclpy.init()` → `FaceDetectNode()` → `rclpy.spin(node)` **卡住等人** |
| ③ | 你 | 终端 2 敲 `ros2 run demo_python_service face_detect_client_node` |
| ④ | 客户端 | `__init__()`：连上 `face_detect` 服务，读入 `2026-10-02_14-13.png` |
| ⑤ | 客户端 | `send_request()`：`wait_for_service` 确认服务在线 |
| ⑥ | 客户端 | `cv2_to_imgmsg()` 把 OpenCV 图**打包**成 ROS 消息 |
| ⑦ | 客户端 | `call_async()` 把请求**发出去**，立刻拿到一张 "取餐号"（future） |
| ⑧ | 客户端 | `spin_until_future_complete()` **盯住取餐号等结果** |
| ⑨ | rclpy 框架 | 把请求**送到服务端**，自动调用服务端的 `face_detect_callback()` |
| ⑩ | 服务端 | 回调里：`imgmsg_to_cv2()` **拆包** → `face_locations()` 检测 → 填 `response` → `return` |
| ⑪ | rclpy 框架 | 把 `response` **送回客户端**，future 变成"完成" |
| ⑫ | 客户端 | `future.result()` 取出坐标 → `show_response()` 画蓝框 → `cv2.imshow` 弹窗 |
| ⑬ | 你 | 按任意键，客户端退出；服务端还在等着下一个请求 |

★ 第 ⑨ 步和第 ⑪ 步是**你写的代码里找不到的**，是 rclpy 在幕后干的。这一点在第三部分会重点讲。

---

## 1.5 开始前先记住 6 个概念

| 概念 | 大白话 | 本项目里的例子 |
| --- | --- | --- |
| **图片** | 电脑眼里就是一堆数字（像素） | `cv2.imread()` 读出来的东西 |
| **numpy 数组** | 那堆数字在 Python 里的形态，OpenCV 用它表示图片 | `image` 这个变量 |
| **服务（Service）** | 一种"你问我答"的通信方式，一问一答 | `/face_detect` |
| **请求 / 响应** | 问的内容 / 答的内容 | `request.image` / `response.number` |
| **回调（callback）** | 你提前写好、留给别人在合适时机调用的函数 | `face_detect_callback` |
| **节点（Node）** | ROS 2 里一个能干活的程序单位 | `face_detect_node`、`face_detect_client_node` |

# 第二部分 · 再看分部

## 2.0 编译期：三个文件怎么变成命令

你写的 `.py` 文件**不会自动**变成 `ros2 run` 能用的命令，中间要靠 `setup.py`。

**① `setup.py` 的 `entry_points` —— 把文件名映射成命令名**

```python
entry_points={
    'console_scripts': [
        'learn_face_detect = demo_python_service.learn_face_detect:main',
        'face_detect_node = demo_python_service.face_detect_node:main',
        'face_detect_client_node = demo_python_service.face_detect_client_node:main',
    ],
},
```

读法：`命令名 = 包名.文件名:函数名`

意思是"当用户敲 `ros2 run demo_python_service learn_face_detect` 时，去执行 `demo_python_service/learn_face_detect.py` 里的 `main` 函数"。

★ 这也是为什么 `learn_face_detect.py` 自己没写调用 `main()` 的语句，`ros2 run` 却依然能跑 —— **入口脚本替你调用了**。

**② `setup.py` 的 `data_files` —— 把图片也装进去**

```python
data_files=[
    ('share/' + package_name + "/resource",
        ['resource/default.jpg', 'resource/2026-10-02_14-13.png']),
],
```

因为运行时代码不在 `src/` 里，而是在 `install/` 里，所以图片也必须被"搬"过去一份。

**③ `chapt4_interfaces` 包的 `srv/FaceDetector.srv` —— 生成服务类**

`colcon build` 会把这个 `.srv` 文件翻译成 Python 类 `FaceDetector`，服务端和客户端都 `import` 它。

## 2.1 文件一：learn_face_detect.py（单机版）

📄 `src/demo_python_service/demo_python_service/learn_face_detect.py`（60 行）

**它干什么**：把 `default.jpg` 读进来，找出所有人脸，画绿框，弹窗显示。

**它的结构**：整个文件**只有一个函数** `main()`。

```
import 部分（4 行）
    ↓
def main():        ← 从头到尾一条直线
    找图片路径
    读图
    检测
    画框
    显示
```

**关键代码**：

```python
# 找图片：去 install/ 的 share 目录里找，不是 src/
default_image_path = os.path.join(
    get_package_share_directory('demo_python_service'),  # 返回 install/.../share/demo_python_service
    'resource',
    'default.jpg'
)

image = cv2.imread(default_image_path)          # 读图 → numpy 数组

face_locations = face_recognition.face_locations(   # ★ 核心：检测
    image, number_of_times_to_upsample=1, model="hog"
)                                               # 返回 [(top,right,bottom,left), ...]

for top, right, bottom, left in face_locations: # 逐张脸画框
    cv2.rectangle(image, (left, top), (right, bottom), (0, 255, 0), 4)

cv2.imshow("Face Detection Result", image)      # 弹窗
cv2.waitKey(0)                                  # 不加这句窗口一闪而过
```

**⚠ 这个文件有一个小缺陷**

文件结尾**少了两行**：

```python
if __name__ == '__main__':
    main()
```

后果：

- `python3 learn_face_detect.py` → **没有任何反应**（因为只"定义"了 `main`，没"调用"它）
- `ros2 run demo_python_service learn_face_detect` → **能跑**（入口脚本替你调了）

建议补上，这样两种方式都能跑。

## 2.2 文件二：face_detect_node.py（服务端）

📄 `src/demo_python_service/demo_python_service/face_detect_node.py`（71 行）

**它干什么**：开一个叫 `face_detect` 的服务窗口，一直等客人来。客人发来图片，它就检测，然后把坐标报回去。

**它的结构**：1 个类 + 3 个函数。

```
class FaceDetectNode(Node):         ← 继承 ROS 2 的 Node 基类
    def __init__(self):             ← 开店准备（注册服务、准备工具）
    def face_detect_callback(...):  ← ★ 客人来了才执行（核心逻辑）

def main(args=None):                ← 总开关
```

**生命周期**：

```
rclpy.init()  →  FaceDetectNode()  →  rclpy.spin(node)  →  Ctrl+C  →  收尾
   初始化           开店准备            一直等人             退出
```

**关键代码**：

```python
# ① 开店准备：注册服务
self.srv = self.create_service(
    FaceDetector,               # 卖什么（类型）
    'face_detect',              # 窗口挂牌（服务名）
    self.face_detect_callback   # 客人来了打这个电话（回调）★ 注意没有括号
)

# ② 客人来了才执行这里
def face_detect_callback(self, request, response):
    if request.image.data:
        cv_image = self.bridge.imgmsg_to_cv2(request.image, desired_encoding='bgr8')
    else:
        cv_image = cv2.imread(self.default_image_path)   # 没带图就用默认图

    face_locations = face_recognition.face_locations(cv_image, ...)

    response.use_time = time.time() - start_time
    response.number = len(face_locations)
    for top, right, bottom, left in face_locations:
        response.top.append(top)      # 四组数组按下标一一对应
        response.right.append(right)
        response.bottom.append(bottom)
        response.left.append(left)
    return response                    # ← 返回值被 rclpy 打包发回客户端
```

**小细节**：客户端**总是**会填 `request.image`，所以 `else` 那条读 `default.jpg` 的分支实际走不到，它只是"万一没带图"的保险。

## 2.3 文件三：face_detect_client_node.py（客户端）

📄 `src/demo_python_service/demo_python_service/face_detect_client_node.py`（68 行）

**它干什么**：读一张 png，发给服务端，等服务端报回坐标，画蓝框显示，然后退出。

**它的结构**：1 个类 + 4 个函数。

```
class FaceDetectClientNode(Node):
    def __init__(self):                     ← 准备：连服务、读图
    def send_request(self):                 ← ★ 发请求 + 等结果 + 转交画框
    def show_response(self, response):      ← 按坐标画蓝框

def main(args=None):                        ← 总开关
```

**关键代码**：

```python
# ① 拿到这个服务窗口的"点菜单"
self.client = self.create_client(FaceDetector, 'face_detect')

# ② 确认服务在线
while not self.client.wait_for_service(timeout_sec=1.0):
    self.get_logger().info('服务未就绪，等待中...')

# ③ 打包 + 发送
request = FaceDetector.Request()
request.image = self.bridge.cv2_to_imgmsg(self.image, encoding='bgr8')
future = self.client.call_async(request)          # 下单，立刻拿到"取餐号"

# ④ 等结果
rclpy.spin_until_future_complete(self, future)    # 盯着取餐号等
response = future.result()                        # 凭号取餐

# ⑤ 画框
self.show_response(response)
```

**小细节**：`send_request()` 里传了 `self` 给 `spin_until_future_complete`，**不传会报错**。原因在第三部分 3.6 讲。

## 2.4 服务契约：FaceDetector.srv

📄 `src/chapt4_interfaces/srv/FaceDetector.srv`（8 行）

```
sensor_msgs/Image image   # 请求：一张图
---
int16 number              # 响应：检测到几张脸
float32 use_time          # 响应：花了多少秒
int32[] top               # 响应：每张脸的上边界（数组）
int32[] right             # 响应：每张脸的右边界
int32[] bottom            # 响应：每张脸的下边界
int32[] left              # 响应：每张脸的左边界
```

`---` 上面是**请求**，下面是**响应**。

**为什么坐标要拆成 4 个数组？**

因为 `face_locations()` 原本返回的是"每个元素有 4 个数"的结构：

```python
[(100, 200, 300, 50), (400, 500, 600, 350)]
#  (top, right, bottom, left)
```

但 `.srv` 文件**不支持"结构体数组"**，只支持基本类型数组。所以只能摊平成 4 个平行数组，靠**下标对齐**：

```
response.top    = [100, 400]
response.right  = [200, 500]
response.bottom = [300, 600]
response.left   = [ 50, 350]
        ↑ 第 0 张脸          ↑ 第 1 张脸
```

客户端取的时候也要按下标取：

```python
top, right, bottom, left = response.top[i], response.right[i], response.bottom[i], response.left[i]
```

# 第三部分 · 最后到函数

## 3.0 函数到底是什么

### 3.0.1 定义 vs 调用（最容易混的一步）

```python
def main():          # ← 这是"定义"：只是把做法写下来，不执行
    print("干活")

main()               # ← 这是"调用"：真的去干一次
```

比喻：

- `def main():` = **写菜谱**
- `main()` = **照着菜谱做一次菜**

只写菜谱不做菜，是不会有菜端上来的。`learn_face_detect.py` 就是"只写了菜谱，没做菜"。

### 3.0.2 参数和返回值

```python
结果 = 函数名(原料1, 原料2)
```

- **参数**（括号里的东西）= 喂给函数的**原料**
- **返回值**（`=` 左边接住的东西）= 函数给你的**成品**
- 有的函数没有返回值，只干活（比如 `cv2.rectangle`），那就直接写，不用接

```python
face_locations = face_recognition.face_locations(image)   # 有返回值
cv2.rectangle(image, (left,top), (right,bottom), (0,255,0), 4)  # 没返回值
```

### 3.0.3 `self` 是什么

`self` 就是"**我自己**"。

写在类里面的函数（叫**方法**），第一个参数必须是 `self`，代表"调用我的那个对象"：

```python
class FaceDetectNode(Node):
    def face_detect_callback(self, request, response):
        #                     ↑ 我自己
        self.bridge.imgmsg_to_cv2(...)   # 用"我的" bridge 工具
```

类比：`self.bridge` = "我自己的转换器"，`self.get_logger()` = "我自己的日志本"。**每个节点都有自己的那一套，所以要写 `self.`。**

### 3.0.4 类、对象、构造函数

```python
class FaceDetectNode(Node):     # 类 = 图纸
    def __init__(self):         # 构造函数 = 出厂设置
        ...

node = FaceDetectNode()         # 对象 = 按图纸造一个（这一步会自动执行 __init__）
```

`__init__` 是 Python 里"**创建对象时自动调用**"的特殊函数，你**从来不用手写 `__init__()`**。

## 3.1 ★ 谁调用谁：自动调用 vs 手动调用

这是你问的重点。整个项目一共 **8 个函数**，其中：

> **6 个是"别人自动调用你"，只有 2 个是"你自己手动调用"。**

### 完整清单

| # | 函数 | 谁调用它 | 什么时候 | 类型 |
| --- | --- | --- | --- | --- |
| 1 | `learn_face_detect.py::main()` | setuptools 生成的入口脚本 | `ros2 run ... learn_face_detect` 时 | 🤖 **自动** |
| 2 | `face_detect_node.py::main()` | 同上 | `ros2 run ... face_detect_node` 时 | 🤖 **自动** |
| 3 | `face_detect_client_node.py::main()` | 同上 | `ros2 run ... face_detect_client_node` 时 | 🤖 **自动** |
| 4 | `FaceDetectNode.__init__()` | **Python 语法** | 执行 `FaceDetectNode()` 造对象时 | 🤖 **自动** |
| 5 | `FaceDetectClientNode.__init__()` | **Python 语法** | 执行 `FaceDetectClientNode()` 造对象时 | 🤖 **自动** |
| 6 | `FaceDetectNode.face_detect_callback()` | **rclpy 框架** | **每收到一次 `/face_detect` 请求** | 🤖 **自动（最重要）** |
| 7 | `FaceDetectClientNode.send_request()` | 你写的 `main()` | `main` 第 62 行 `node.send_request()` | ✍️ **手动** |
| 8 | `FaceDetectClientNode.show_response()` | 你写的 `send_request()` | `send_request` 第 44 行 | ✍️ **手动** |

### 怎么一眼分辨？

**在项目里搜一下这个名字，看看有没有出现"带括号的调用"。先搜全部：**

```bash
grep -rn "face_detect_callback" src/
```

```
face_detect_node.py:17:  # 创建服务：...回调 face_detect_callback          ← 注释
face_detect_node.py:18:  self.srv = self.create_service(..., self.face_detect_callback)  ← 传参
face_detect_node.py:30:  def face_detect_callback(self, request, response):   ← 定义
```

**再要求"名字后面紧跟左括号"（也就是真正的调用）：**

```bash
grep -rn "face_detect_callback(" src/
```

```
face_detect_node.py:30:  def face_detect_callback(self, request, response):
```

只剩 `def` 这一行了 —— 因为 `def` 后面也有括号。

**最后确认一下有没有真正的调用：**

```bash
grep -rn "face_detect_callback(request" src/
```

```
（无输出）
```

**没有任何地方写 `self.face_detect_callback(request, response)`。** 说明它不是你调的，是 rclpy 调的。

> 第 18 行是 `self.face_detect_callback)`，**名字后面紧跟的是右括号，不是左括号** —— 这就是"传电话号"而不是"打电话"。

这就是判断标准：

> **有括号 `func()` = 调用；没括号 `func` = 只是把函数当"电话号码"传给别人。**

### 三类"自动调用"分别是谁在调

| 自动调用的类型 | 谁在幕后 | 涉及函数 |
| --- | --- | --- |
| **入口调用** | `setup.py` → setuptools 生成的脚本 | 三个 `main()` |
| **构造调用** | Python 语言本身（`类名()` 时触发 `__init__`） | 两个 `__init__()` |
| **回调调用** | `rclpy.spin()` 内部的执行器循环 | `face_detect_callback()` |

★ **只有第三类是 ROS 2 特有的**。前两类是普通 Python 知识，跟 ROS 没关系。

## 3.4 face_detect_node.py 的 3 个函数

### `main(args=None)` — 总开关

```python
def main(args=None):
    rclpy.init(args=args)        # ① 初始化 ROS 2
    node = FaceDetectNode()      # ② 开店（会触发 __init__）

```

**执行顺序**：

```
rclpy.init()  →  __init__()  →  spin() 卡住  →  Ctrl+C  →  destroy/shutdown
```

### `__init__(self)` — 开店准备

```python
def __init__(self):
    super().__init__('face_detect_node')      # 让父类 Node 先做好基础工作
    self.srv = self.create_service(...)       # ★ 注册服务（留电话）
    self.bridge = CvBridge()                  # 准备图像转换器
    self.number_of_times_to_upsample = 1
    self.model = "hog"
    self.default_image_path = os.path.join(...)  # 算好默认图路径
    self.get_logger().info('Face Detect Service is ready.')
```

**它是自动调用的**（Python 执行 `FaceDetectNode()` 时触发），**但你不会看到 `__init__()` 这个写法**。

★★ 重点：`create_service` 这一句**没有开始检测**，它只是"**把档口开起来、把电话留好**"。真正的检测在 `face_detect_callback` 里，**等客人来了才做**。

### `face_detect_callback(request, response)` — 干活的

**这是全项目唯一一个"框架自动调用"的业务函数。**

```python
def face_detect_callback(self, request, response):
    if request.image.data:
        cv_image = self.bridge.imgmsg_to_cv2(request.image, desired_encoding='bgr8')
    else:
        cv_image = cv2.imread(self.default_image_path)

    start_time = time.time()
    face_locations = face_recognition.face_locations(cv_image, 1, "hog")
    response.use_time = time.time() - start_time
    response.number = len(face_locations)
    for top, right, bottom, left in face_locations:
        response.top.append(top); response.right.append(right)
        response.bottom.append(bottom); response.left.append(left)
    return response
```

**它的两个参数从哪来？**

不是你自己造的，是 **rclpy 收到请求后拆好、喂给它的**：

- `request` = 客户端发来的东西（里面有 `request.image`）
- `response` = 一个空的响应对象，**等着你往里填**

**它的返回值去哪了？**

你 `return response` 之后，rclpy 把它打包，通过网络发回给客户端。所以 **`return` 这一句就是"回复客人"**。

### `send_request(self)` — 主流程

```python
def send_request(self):
    while not self.client.wait_for_service(timeout_sec=1.0):   # ① 确认开门
        self.get_logger().info('服务未就绪，等待中...')

    request = FaceDetector.Request()                            # ② 拿一张空白订单
    request.image = self.bridge.cv2_to_imgmsg(self.image, 'bgr8')  # ③ 打包图片

    future = self.client.call_async(request)                    # ④ 下单，拿取餐号
    rclpy.spin_until_future_complete(self, future)              # ⑤ 盯号等结果
    response = future.result()                                  # ⑥ 凭号取结果

    self.get_logger().info(f'人脸检测结果: {response.number} 张人脸，耗时 {response.use_time:.4f} 秒')
    self.show_response(response)                                # ⑦ 转交画框
```

### `show_response(self, response)` — 画框

```python
def show_response(self, response):

    cv2.imshow('Face Detection Result', self.image)
    cv2.waitKey(0)
```

## 3.6 ★ 四个关键调用的生活化比喻

把整个流程想象成**去饭店点一份现炒的菜**。

### ① `create_service` —— 开档口 + 留电话

```python
self.srv = self.create_service(FaceDetector, 'face_detect', self.face_detect_callback)
```

> 比喻：你**不是现在就开火炒菜**。你只是跟 ROS 说三件事：
> - `FaceDetector` = **卖什么菜**（菜品标准/菜单格式）
> - `'face_detect'` = **档口挂的牌子**（客人按这个名字找你）
> - `self.face_detect_callback` = **留的电话号码**（客人来了打这个电话）
>
> 然后你就**收摊去休息了**，等人来点。

⚠️ **初学者最容易错的地方**：第三个参数写的是 `self.face_detect_callback`，**没有括号**。

| 写法 | 含义 |
| --- | --- |
| `self.face_detect_callback` | ✅ 把**电话号码**给他（以后有事打这个） |
| `self.face_detect_callback()` | ❌ 现在**立刻打这个电话**（而且现在还没有请求参数，会报错） |

### ② `rclpy.spin` —— 店员在柜台后面一直待命

```python
rclpy.spin(node)
```

> 比喻：`spin` 是一个**永远不下班的店员**，站在门口，重复做一件事：
>
> ```
> while 程序还在运行:
>     有没有新请求？── 有 ──▶ 调用 face_detect_callback(请求, 空响应)
>                    └─ 没有 ──▶ 继续站着等
> ```

**为什么必须有它？**

```python
rclpy.init()
node = FaceDetectNode()    # 档口开好了
                            # ← 不加 spin，程序到这里就结束了！
```

没有 `spin`，程序会**瞬间跑完退出**，就像"档口刚开张就关门"。

★ 所以 `rclpy.spin(node)` 这一行**永远不会返回**，直到你按 `Ctrl+C`。这也是为什么 `node.destroy_node()` 写在它**后面** —— 只有按了 Ctrl+C 才轮得到执行。

### ③ `call_async` —— 点外卖，下单后给你一张取餐号

```python
future = self.client.call_async(request)
```

> 比喻：你把订单交给骑手，**不是**傻站在柜台前干等到菜做好，而是**立刻拿到一张小票**。

- `async` = **异步** = 不堵在这儿等
- 返回值 `future` **不是结果本身**，而是"**结果将来会有**"的凭证（取餐号）
- 这一刻 `future` 里面是**空的**，菜还没炒好

★ 记住：`call_async` 之后**你还什么都没有**，只有一个号。

### ④ `spin_until_future_complete` —— 拿着号盯取餐屏

```python
rclpy.spin_until_future_complete(self, future)
response = future.result()
```

> 比喻：这一步才是真正"**等**"。
> 你拿着号，站在取餐口盯着屏幕，**直到自己的号亮起来**才走开。

它同时在干两件事：

1. **让 rclpy 继续转起来**（收发网络消息 —— 不转，结果永远送不到你手上）
2. **一旦 `future` 完成就立刻返回**

**为什么第一个参数要传 `self`？**

因为它要"**借用你这个节点**"来转（处理回调、收消息）。你得把自己也交出去。这也是为什么它是个**普通函数**（`rclpy.spin_until_future_complete`），而不是你节点的方法（不是 `self.client.xxx`）。

★ 三句连着记：

```
future = self.client.call_async(request)            # 下单，拿号
rclpy.spin_until_future_complete(self, future)      # 盯屏，等号
response = future.result()                          # 凭号取餐
```

### ⑤ 附赠：`wait_for_service` —— 先打电话问"开门了吗"

```python
while not self.client.wait_for_service(timeout_sec=1.0):
    self.get_logger().info('服务未就绪，等待中...')
```

> 比喻：到了饭店门口，先确认档口开了没有。
> `timeout_sec=1.0` = 打一次电话等 1 秒，没人接就挂掉、打条日志、再打一次。
> `while not` = **只要还没开门，就一直问**。

⚠️ 少了这个循环，如果服务端还没起来就发请求，ROS 2 会**直接抛异常**。

### 一张表总结

| 调用 | 生活比喻 | 一句话记住 |
| --- | --- | --- |
| `create_service` | 开档口、留电话 | 现在**不干活**，只是把联系方式给出去 |
| `create_client` | 拿一张点菜单 | 知道去哪儿点、按什么格式点 |
| `rclpy.spin` | 店员一直待命 | 不让程序退出，**永远不返回** |
| `wait_for_service` | 打电话问开门没 | 没开门就一直问 |
| `call_async` | 下单，拿取餐号 | 立刻返回，**手里只有号** |
| `spin_until_future_complete` | 盯取餐屏等号 | 真正"等"的地方，**要传 self** |
| `future.result()` | 凭号取餐 | 到这一步才拿到真正结果 |

# 第四部分 · 常见疑问

### Q1：为什么客户端要 `import cv2`，但它不检测？

因为要**读图**和**画框**。检测交给服务端了，但"把图片读进来"和"把框画上去"还是客户端自己的事。

### Q2：为什么 `create_service` 的第 3 个参数不加括号？

加括号是"**现在就执行**"，不加括号是"**把这个函数交给你，以后你看着办**"。服务注册是把回调**登记**出去，不是立刻执行。

### Q3：`spin` 和 `spin_until_future_complete` 有什么区别？

| | `rclpy.spin(node)` | `rclpy.spin_until_future_complete(self, future)` |
| --- | --- | --- |
| 等多久 | 永远（到 Ctrl+C） | 等到 `future` 完成就返回 |
| 用在哪 | 服务端（要常驻） | 客户端（拿到结果就走） |
| 传参 | `(node)` | `(self, future)` |

一句话：**服务端用 `spin`，客户端用 `spin_until_future_complete`。**

### Q4：为什么服务端回调的坐标要拆成 4 个数组？

`.srv` 不支持"结构体数组"，只能摊平成 4 个基本类型数组，靠**下标对齐**。

### Q5：`learn_face_detect.py` 为什么 `python3` 直接跑没反应？

因为它只写了 `def main():`（菜谱），没写 `main()`（做菜）。补上这两行即可：

```python
if __name__ == '__main__':
    main()
```

`ros2 run` 能跑，是因为入口脚本替你调用了 `main`。

### Q6：我记得检测时用过 `number_of_times_to_upsample`，它干嘛的？

上采样次数。**值越大越容易检测到小人脸，但越慢**。本项目两个文件都设成 `1`。想试效果，把服务端 `__init__` 里的 `self.number_of_times_to_upsample` 改成 `2` 再重编，看看耗时变化。

### Q7：`model="hog"` 和 `"cnn"` 什么区别？

- `"hog"`：用 CPU，**快**，够用
- `"cnn"`：更**准**，但很慢，最好有 GPU

# 第六部分 · 核心要点总结

1. **三个文件的分工**：单机练习 / 服务端（常驻）/ 客户端（一次性）。
2. **核心代码只有一句**：`face_recognition.face_locations()`，三个文件用的是同一个本领。
3. **检测只在服务端**：客户端不 `import face_recognition`，它只打包、发送、收坐标、画框。
4. **8 个函数里，6 个是自动调用的**：三个 `main`（入口脚本）、两个 `__init__`（Python 语法）、一个 `callback`（rclpy）。
5. **只有 2 个是你手动调的**：`send_request()` 和 `show_response()`。
6. **判断标准**：**有括号 `f()` 是调用，没括号 `f` 是传电话号**。
7. **`create_service` 不干活**，它只是开档口、留电话；真正干活的是 `callback`。
8. **`spin` 永不返回**，它是"店员一直待命"；服务端靠它活着。
9. **`call_async` + `spin_until_future_complete` = 下单 + 等餐**，前者立刻返回一个 `future`，后者才真正等待。
10. **`spin_until_future_complete` 必须传 `self`**，因为它要借用你的节点来收发消息。
11. **`cv_bridge` 是双向翻译官**：客户端 `cv2_to_imgmsg` 打包，服务端 `imgmsg_to_cv2` 拆包。
12. **坐标拆成 4 个数组**是因为 `.srv` 不支持结构体数组，靠下标对齐。
13. **`learn_face_detect.py` 缺 `if __name__ == '__main__':`**，建议补上。

```
【单机版】
ros2 run ... learn_face_detect
   └─▶ main()  ─▶ get_package_share_directory / os.path.join / cv2.imread
                ─▶ face_recognition.face_locations

【服务版 · 服务端】
ros2 run ... face_detect_node
   └─▶ main()  ─▶ rclpy.init
                ─▶ FaceDetectNode()  ══Python 自动══▶ __init__()
                │                                        └─▶ create_service(..., callback)  ← 只登记，不执行
                └─▶ rclpy.spin(node)  ══rclpy 自动══▶ face_detect_callback(request, response)
                                                          ├─▶ imgmsg_to_cv2 / cv2.imread
                                                          ├─▶ face_recognition.face_locations
                                                          └─▶ return response  ← 回复客户端

【服务版 · 客户端】
ros2 run ... face_detect_client_node
   └─▶ main()  ─▶ rclpy.init
                ─▶ FaceDetectClientNode()  ══Python 自动══▶ __init__()
                │                                             └─▶ create_client / cv2.imread
                └─▶ send_request()
                      ├─▶ wait_for_service（确认开门）
                      ├─▶ cv2_to_imgmsg（打包）
                      ├─▶ call_async（下单，拿 future）
                      ├─▶ spin_until_future_complete(self, future)（盯号等）
                      ├─▶ future.result()（取结果）
                      └─▶ show_response(response)
                            └─▶ cv2.rectangle / cv2.imshow / cv2.waitKey
```
